# download-speed

Консольный скрипт на Node.js, который замеряет скорость скачивания по URL.

Скрипт делает к адресу N запросов **последовательно**: следующий уходит только после того, как тело предыдущего ответа дочитано до последнего байта. Потом он считает среднее время запроса, общий объём скачанного и скорость скачивания.

## Требования

- Node.js 18.18 или новее. Проверено на Node.js 22.
- Внешних зависимостей нет, `npm install` не нужен. Используется только стандартная библиотека: `fetch`, `AbortSignal.timeout`, `util.parseArgs`, `node:test`.

## Запуск

```bash
git clone <адрес репозитория>
cd download-speed
node src/cli.js "https://speed.cloudflare.com/__down?bytes=10000000"
```

То же самое через npm (аргументы передаются после `--`):

```bash
npm start -- "https://speed.cloudflare.com/__down?bytes=10000000" -n 5
```

URL с `?` и `&` лучше брать в кавычки, иначе их перехватит оболочка.

### Опции

| Опция | По умолчанию | Описание |
|---|---|---|
| `<url>` | — | адрес, к которому делать запросы; только `http://` и `https://` |
| `-n`, `--count <число>` | 10 | сколько запросов сделать подряд, целое число от 1 |
| `-t`, `--timeout <секунды>` | 30 | таймаут одного запроса, **включая скачивание тела**; можно дробное |
| `-h`, `--help` | — | справка |

## Единицы измерения

Все приставки десятичные (СИ), как у провайдеров и спидтестов:

- **Скорость** выводится в **Мбит/с**, где 1 Мбит = 10^6 бит. В скобках та же скорость в **МБ/с**, где 1 МБ = 10^6 байт. 1 МБ/с = 8 Мбит/с.
- **Объём** выводится в **МБ** (10^6 байт). В итогах дополнительно указано точное число байт.
- **Время** выводится в миллисекундах.

## Как считается

**Время запроса** отсчитывается от момента отправки запроса до получения последнего байта тела. Тело читается потоком: размер каждого пришедшего куска прибавляется к счётчику, а сам кусок выбрасывается. Поэтому большой файл не занимает память целиком. Если сервер перенаправляет запрос (3xx), время редиректа тоже входит в замер.

**TTFB** (время до заголовков) отсчитывается от отправки запроса до получения статуса и заголовков ответа. Это время сервера на ответ плюс сетевая задержка, без скачивания тела.

**Скорость** считается по формуле:

```
скорость = сумма байт успешных запросов / сумма времени успешных запросов
```

Это **не** среднее арифметическое скоростей отдельных запросов. Пример: 10 МБ скачались за 1 с, и ещё 10 МБ за 9 с. Всего скачано 20 МБ за 10 с, то есть 2 МБ/с. Среднее скоростей дало бы (10 + 1.11) / 2 ≈ 5.56 МБ/с, и это завышенная цифра, потому что быстрый запрос весит в ней столько же, сколько медленный.

**Среднее время запроса** — среднее арифметическое времени успешных запросов. Минимум и максимум показывают разброс.

**Заголовки запроса:**

- `Accept-Encoding: identity` просит сервер не сжимать ответ. `fetch` в Node.js сам распаковывает gzip и brotli. Если ответ придёт сжатым, мы посчитаем распакованные байты, а не те, что реально прошли по сети, и скорость окажется завышенной. Если сервер проигнорирует `identity` и всё равно сожмёт ответ, скрипт посчитает уже распакованный объём.
- `Cache-Control: no-cache` просит промежуточные кеши (CDN, прокси) не отдавать сохранённую копию без проверки у источника. Собственного HTTP-кеша у `fetch` в Node.js нет.

**Почему первый запрос обычно медленнее.** Перед первым запросом нужно разрезолвить DNS, установить TCP-соединение и пройти TLS-рукопожатие. Последующие запросы идут по тому же соединению (keep-alive), а TCP успевает разогнаться. Кроме того, CDN может прогревать кеш на первом обращении. В примере выше это видно по TTFB: 512 мс у первого запроса против 50–100 мс у остальных. Первый запрос не выбрасывается из расчёта, потому что это часть реального скачивания.

## Тесты

```bash
npm test
```

Тесты используют `node:test` и поднимают локальный HTTP-сервер на случайном порту, так что интернет для них не нужен. Что проверяется:

- 10 запросов: каждый получил ровно N байт, сервер ни разу не видел больше одного запроса одновременно (то есть запросы действительно последовательные), до сервера дошёл заголовок `Accept-Encoding: identity`;
- HTTP 500 записывается как ошибка, а серия продолжается;
- таймаут срабатывает, когда заголовки пришли, а тело зависло;
- недоступный хост даёт понятную ошибку (`ECONNREFUSED`), а не падение скрипта;
- арифметика сводки на примере, где среднее скоростей и правильная скорость различаются.

## Коды выхода

| Код | Значение |
|---|---|
| 0 | хотя бы один запрос завершился успешно |
| 1 | все запросы завершились ошибкой |
| 2 | неверные аргументы командной строки |
